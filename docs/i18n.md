# Interface localisation

The interface ships in Simplified Chinese, Traditional Chinese, Japanese and
English. Chinese source strings are the lookup keys: the code keeps writing
`'播放队列'`, and `AppLocalizations` maps it to the active locale through
`assets/l10n/<tag>.json`.

## Wiring text

| Where the string ends up | How to translate it |
| --- | --- |
| Widget text | `TrText('播放队列')` or `Text(context.tr('播放队列'))` |
| Tooltip / semantics / slider label | `context.tr('上一首')`; the shared `Accessible*` widgets in `lib/widgets/accessible_controls.dart` already call it for `tooltip`, `message`, `semanticLabel` and `label` |
| Dialog, snackbar, sheet title | `TrText(...)` inside the widget, `context.tr(...)` when a `String` API wants one |
| Material string parameter (`hintText`, `labelText`, `title`, `message`) | `context.tr(...)` at the call site |
| A widget's own `String` parameter rendered as text | translate inside that widget's `build`, once — see `ApplePageTitle`, `_LegacySettingRow` |

Never translate data: catalogue titles, artist names, lyric lines, file names
and user input stay as they are. They are passed to `Text`, not `TrText`.

## Interpolated messages

Values stay in the code, placeholders live in the table:

```dart
TrText('${queue.length} 首')
```

```json
"{count} 首": "{count} 首"
```

The key in the table spells the dynamic part as `{name}`. `AppLocalizations`
matches the runtime string against that pattern and substitutes the value, so
the same mechanism covers messages the state layer builds
(`下载失败（HTTP 500）。` → key `下载失败（HTTP {code}）。`). The checker accepts
the literal interpolation syntax in code (`'$count 首'`,
`'${track.title} · ${count} 张'`) as covered by the matching `{count}` /
`{title}` key.

Keep the interpolated prefix unique enough for the pattern to match: `{name}`
with `.*?` between fixed segments means two keys must not differ only in the
middle of a number.

## Data-layer messages

`lib/state/`, `lib/data/` and `lib/gateway/` produce ready-made Chinese
messages (errors, fallbacks) that the UI renders later. A file that is entirely
such strings carries an

```dart
// i18n:data — these strings are keys; the widget that shows them calls
// context.tr.
```

marker near the top. The checker skips them for *wiring* but still requires
every one of their strings to exist in the tables, and the render site must
use `TrText` / `context.tr`.

A file that mixes catalogue data with interface strings (for example
`lib/data/catalog.dart`) does not take the file-level marker. Mark only the
interface literals with an inline `// i18n:key` comment:

```dart
_homeError = '曲库加载失败，请检查网络后重试。'; // i18n:key
```

That keeps chart names, album types and other catalogue values out of the
tables while still making the error message a checked key.

## Checker

```
python tool/check_i18n.py             # gate: exit 1 when something is unwired
python tool/check_i18n.py --verbose   # list every finding
python tool/check_i18n.py --keys      # dump every key the code emits
```

It fails when

1. a Chinese string reaches `Text`, `SelectableText`, `Tooltip.message`,
   `Semantics.label`, `IconButton.tooltip`, `NavigationDestination.label`,
   `Chip.label`, `Image.semanticLabel`, `SearchBar.hintText`,
   `SnackBarAction.label`, `PopupMenuButton.tooltip` or `AppleListTile`'s
   `title` / `subtitle` without `context.tr` and without being a `String`
   parameter of a widget that translates it (the `TRANSLATING_WIDGETS` list in
   the script),
2. the four tables disagree about their key set,
3. a key the code emits is missing from the tables, or
4. a table key is no longer produced by any code.

The scanner walks brackets once, so strings inside ternaries, collection
literals, switch expressions and generic constructors (`Widget<T>(...)`) keep
the call and named argument that contain them.

`dart test` covers the runtime side: `test/l10n_test.dart` loads all four
tables, checks key parity, checks that the placeholder names match between key
and translation, and checks that the fallback locale never leaks `{...}` into
the UI.

## Adding a locale

1. Add the tag to `AppLanguage` and `AppLocalizations.supportedLocales`.
2. Copy `assets/l10n/en.json` and translate the values; keep the keys and
   placeholders untouched.
3. `flutter test` fails until the new table is complete.
